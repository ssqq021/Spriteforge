# 技术架构

## 推荐策略

在现有 GitHub Pages 工具基础上渐进升级，不立即建设复杂 SaaS。

## 阶段 A：本地优先 Web App

- React + TypeScript + Vite
- Zustand
- IndexedDB
- Web Workers
- FFmpeg.wasm
- Canvas / OffscreenCanvas
- JSZip

优点：

- 素材不必上传
- 节省服务器成本
- 隐私友好
- 可继续部署 GitHub Pages

## 阶段 B：桌面增强

当浏览器性能成为瓶颈时增加：

- Tauri
- Rust/FFmpeg 原生处理
- 本地文件系统
- 大文件支持

## 阶段 C：云端 AI

- Next.js 或独立管理端
- FastAPI
- PostgreSQL
- Redis Queue
- S3/R2
- GPU Worker
- WebSocket/SSE 进度

## Monorepo

```text
apps/
  web/
  api/
packages/
  core/
  image-pipeline/
  export-schema/
  ui/
unity-plugin/
workers/
  ai/
```

现阶段可先保持简单目录，重构时再迁移 pnpm workspace。

## 关键设计

- 处理任务采用不可变版本
- 参数与产物分离
- 所有导出由同一份 metadata 驱动
- Web 与 Unity 共用 JSON Schema
- 大计算放入 Worker
